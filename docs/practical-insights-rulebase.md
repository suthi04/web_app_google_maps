# Rule-based: “เรื่องที่ควรรู้ก่อนไป” สำหรับร้านอาหาร

เอกสารนี้บันทึกที่มาของหมวด กติกาที่ระบบใช้ และข้อจำกัด เพื่อให้ตรวจสอบย้อนหลังได้

## หลักการออกแบบ

ส่วนนี้ไม่ใช่การเอาข้อความสรุปที่เตรียมไว้ไปแสดงกับทุกร้าน ระบบมีเพียง “หมวดและคำตรวจจับ” ที่เตรียมไว้ ส่วนข้อสรุปของแต่ละร้านจะเกิดขึ้นต่อเมื่อพบคำดังกล่าวในรีวิวจริง และทุกการ์ดต้องมี `review_id` สำหรับเปิดกลับไปดูข้อความต้นฉบับได้

เราแยกอารมณ์รายประเด็น เพราะรีวิวหนึ่งข้อความอาจชมอาหารแต่ตำหนิบริการได้ การใช้อารมณ์รวมของทั้งรีวิวแทนทุกประเด็นจึงทำให้ความหมายผิด งาน SemEval-2014 วางโจทย์ Aspect-Based Sentiment Analysis สำหรับรีวิวร้านอาหารไว้ในลักษณะนี้ และมีสถานะ `conflict` สำหรับความคิดเห็นที่ขัดกันด้วย ([Pontiki et al., 2014](https://aclanthology.org/S14-2004/))

ชุดข้อมูล ASAP มีรีวิวร้านอาหารจริง 46,730 รีวิวที่มนุษย์กำกับ 18 หมวดย่อย และแยกหัวข้อที่มีผลก่อนเดินทางไว้อย่างละเอียด เช่น เวลารอคิว ความเร็วในการสั่ง/เสิร์ฟ ที่จอดรถ ระดับราคา ความคุ้มค่า เสียง พื้นที่นั่ง ความสะอาด การเดินทาง และความง่ายในการหาร้าน ([Bu et al., 2021](https://aclanthology.org/2021.naacl-main.167/)) หมวดเหล่านี้จึงเป็นฐานหลักของ taxonomy ในระบบ

ชุดข้อมูล GERestaurant สนับสนุนหมวดอาหาร บริการ บรรยากาศ ราคา และระบุว่าบริการครอบคลุมเวลารอและบริการซื้อกลับ ([Hellwig et al., 2024](https://aclanthology.org/2024.konvens-main.14/)) งานภาษาไทยที่ใช้ Wongnai Review Dataset ก็ใช้หมวดคุณภาพอาหาร ราคา บริการ และบรรยากาศ จึงช่วยยืนยันว่าหมวดหลักยังเหมาะกับรีวิวร้านอาหารภาษาไทย ([Multi-label Sentiment Analysis Model for Thai Language Review of Restaurant](https://so09.tci-thaijo.org/index.php/PMR/article/view/6469)) งานวิเคราะห์รีวิวออนไลน์อีกชิ้นพบหัวข้อเด่นเรื่องการรอ อาหาร สภาพแวดล้อม และคุณภาพบริการ และรายงานความสัมพันธ์เชิงลบระหว่างความคิดเห็นเรื่องการรอกับคะแนนรวม จึงให้น้ำหนักหัวข้อคิวค่อนข้างสูงในหน้าแสดงผล ([Baek & Choe, 2025](https://doaj.org/article/73a3b9c6ea704c62aa667c7cc7b47354))

## การตรวจข้อมูลในโครงการ

ตรวจรีวิวร้านอาหารที่ไม่ซ้ำกัน 241 ข้อความจาก `sample_reviews.json`, `labeled_reviews.json` และผลวิเคราะห์ในฐานข้อมูล ณ วันที่ 18 กรกฎาคม 2026 โดยไม่นำชื่อผู้รีวิวหรือข้อมูลส่วนบุคคลมาใช้ จำนวนข้อความที่กฎปัจจุบันตรวจพบอย่างน้อยหนึ่ง cue คือ:

| หัวข้อ | รีวิวที่พบ cue |
|---|---:|
| ราคาและความคุ้มค่า | 70 |
| พื้นที่นั่งและความสบาย | 20 |
| คิวและเวลารอ | 15 |
| ที่จอดรถ | 11 |
| ความสะอาดและห้องน้ำ | 6 |
| ความหนาแน่นและเสียง | 5 |
| ครอบครัว กลุ่ม และการเข้าถึง | 5 |
| การเดินทางและทางเข้าร้าน | 3 |
| การชำระเงิน | 2 |
| ซื้อกลับและจัดส่ง | 2 |
| การจอง/ความพร้อม และข้อจำกัดด้านอาหาร | ยังไม่พบในชุดนี้ |

ตัวเลขนี้ใช้ตรวจว่าคำศัพท์สอดคล้องกับภาษาที่มีอยู่ในโครงการเท่านั้น ไม่ใช่สถิติแทนร้านอาหารไทยทั้งหมด และไม่ใช่ค่าความแม่นยำของโมเดล

## หมวดที่ระบบตรวจ

1. ข้อจำกัดด้านอาหาร เช่น เจ มังสวิรัติ วีแกน ฮาลาล และการแพ้อาหาร
2. การจองและความพร้อม เช่น รับจอง โต๊ะเต็ม ร้านปิด หรือเมนูหมด
3. คิวและเวลารอ เช่น รอไม่นาน คิวยาว เสิร์ฟเร็ว หรือบริการช้า
4. ที่จอดรถ เช่น มีที่จอดรถ หาที่จอดยาก หรือที่จอดน้อย
5. การเดินทางและทางเข้าร้าน เช่น หาง่าย ติดถนนใหญ่ ซอยลึก หรือทางเข้าหายาก
6. การชำระเงิน เช่น รับบัตร พร้อมเพย์ หรือรับเฉพาะเงินสด
7. ราคาและความคุ้มค่า เช่น ราคาไม่แพง คุ้มค่า ราคาแรง หรือไม่คุ้ม
8. ความหนาแน่นและเสียง เช่น เงียบสงบ คนแน่น หรือเสียงดัง
9. พื้นที่นั่งและความสบาย เช่น แอร์เย็น นั่งสบาย ร้อน หรือคับแคบ
10. ความสะอาดและห้องน้ำ เช่น ร้านสะอาด ห้องน้ำโทรม หรือโต๊ะเหนียว
11. ครอบครัว กลุ่ม และการเข้าถึง เช่น เก้าอี้เด็ก รถเข็น วีลแชร์ หรือกลุ่มใหญ่
12. ซื้อกลับและจัดส่ง เช่น ซื้อกลับได้ หรือไม่มีเดลิเวอรี

หมวดอาหารเฉพาะ การจ่ายเงิน การจอง และการเข้าถึงเป็นกฎผลิตภัณฑ์ที่เพิ่มเพราะมีผลต่อการวางแผนก่อนเดินทาง ไม่ได้อ้างว่าเป็น taxonomy มาตรฐานจากทุกงานวิจัย จึงแสดงเฉพาะเมื่อมีหลักฐานตรงในรีวิวเท่านั้น

## ลำดับการทำงาน

1. อ่านข้อความรีวิวและ `review_id` ที่ระบบบันทึกไว้
2. ตรวจ cue ของแต่ละหัวข้อแบบไม่สนช่องว่าง
3. ให้ cue ที่ยาวกว่าชนะคำที่ซ้อนอยู่ เช่น `ไม่แพง` ต้องไม่ถูกนับเป็น `แพง` และ `ไม่สะอาด` ต้องไม่ถูกนับเป็น `สะอาด`
4. แยกหลักฐานเชิงบวก เชิงลบ เป็นกลาง และข้อความที่มีทั้งสองทิศทาง
5. รวมคำพ้องให้อยู่หัวข้อเดียว และนับหนึ่งครั้งต่อหนึ่ง `review_id`
6. ถ้ามีหลักฐานบวกและลบ ระบบแสดงสถานะ “ความคิดเห็นแตกต่างกัน” แทนการเลือกข้างหรือเฉลี่ยทิ้ง
7. ดึงบริบทเวลาเฉพาะที่ปรากฏจริง เช่น `ช่วงเย็น` หรือ `วันหยุด` โดยไม่เดาเวลาเพิ่ม
8. จัดลำดับด้วยจำนวนรีวิวที่ไม่ซ้ำ บวกน้ำหนักผลกระทบต่อการตัดสินใจก่อนไป แล้วแสดงสูงสุด 6 หัวข้อ
9. ทุกการ์ดเปิดรีวิวต้นฉบับที่เป็นหลักฐานได้

อารมณ์รวมจาก WangchanBERTa/Lexicon และ sentiment ของวลีไม่ถูกนำมาตัดสินทิศทางของคำเชิงข้อเท็จจริงโดยอัตโนมัติ เช่น รีวิวที่ชมบริการและมีคำว่า `ที่จอดรถ` จะไม่ถูกสรุปว่า “มีที่จอดรถสะดวก” หากไม่มีคำบอกทิศทางตรง ๆ หลักนี้สอดคล้องกับ ABSA ที่ต้องเชื่อม opinion เข้ากับ target ที่ถูกต้อง ไม่ย้ายความรู้สึกจากอีกประเด็นหนึ่งมาใช้แทน

## รอบปรับปรุงความแม่นยำ 9 สิงหาคม 2026

ตรวจผลจาก analysis ที่บันทึกในเครื่อง 6 รายการร่วมกับชุดตัวอย่างและ regression cases โดยไม่คัดลอกชื่อผู้รีวิว พบความเสี่ยงหลัก 4 แบบ:

1. **คำกำกวมไม่มี target** — `รสชาติแบบนี้หายาก` เคยถูกจับเป็น “ร้านหายาก” จึงยกเลิก cue เดี่ยว `หายาก/หาง่าย` และรับเฉพาะรูปที่ผูกกับร้านหรือเส้นทาง เช่น `ร้านหายาก`, `หาร้านง่าย`, `ทางเข้าหายาก`
2. **ย้าย sentiment ข้ามประเด็น** — `พนักงานบอกที่จอดรถให้และบริการดี` ชมบริการ ไม่ได้ยืนยันว่าที่จอดสะดวก จึงไม่ใช้ sentiment ของวลีกับ cue เชิงข้อเท็จจริงอีกต่อไป
3. **ข้อจำกัดที่ภาษาจริงยังไม่ครอบคลุม** — เพิ่มรูปตรงความหมาย เช่น `ที่จอดเต็ม`, `ต้องจอดริมถนน`, `ไม่เหมาะกับผู้สูงอายุ` และ `ไม่มีทางลาด`
4. **การกระทำที่ยืนยันความเป็นไปได้** — ประโยคว่าผู้รีวิว `สั่งกลับบ้าน` หรือ `ซื้อกลับบ้าน` ถือเป็นหลักฐานทางบวกของช่องทางดังกล่าว แต่ยังแนะนำให้เช็กข้อมูลล่าสุดกับร้าน

การเปลี่ยนแปลงทุกข้อมี regression test ทั้งกรณีที่ควรจับและกรณีที่ต้องไม่จับ โดยจะเพิ่มคำใหม่จาก false positive/false negative ที่ตรวจพบจริงเป็นรอบ ๆ แทนการขยายคลังคำแบบเดา

แนวทางนี้อิงจาก:

- [SemEval-2014 Task 4](https://aclanthology.org/S14-2004/) ซึ่งแยก aspect term/category ออกจาก polarity และรองรับความเห็นขัดแย้ง
- [ASAP](https://aclanthology.org/2021.naacl-main.167/) ซึ่งกำกับหมวดย่อยของร้านอาหาร เช่น queue, parking, transportation, noise, space และ price แยกกัน
- [Implicit Aspect Detection in Restaurant Reviews](https://aclanthology.org/W16-0421/) ซึ่งชี้ว่าคำแสดงความคิดเห็นเดียวอาจกำกวมและต้องตรวจความสัมพันธ์กับ target
- [GERestaurant](https://aclanthology.org/2024.konvens-main.14/) ซึ่งกำกับทั้ง implicit/explicit aspect, category และ sentiment ที่สัมพันธ์กัน
- [งาน Multi-label Sentiment Analysis สำหรับรีวิวร้านอาหารภาษาไทย](https://so09.tci-thaijo.org/index.php/PMR/article/view/6469) ซึ่งแยก Food, Price, Service และ Ambience พร้อม sentiment รายด้าน

## ระดับการพบหลักฐาน

| รีวิวไม่ซ้ำ | ป้ายที่แสดง |
|---:|---|
| 1 | พูดถึง 1 ครั้ง |
| 2–3 | พูดถึงหลายครั้ง |
| 4 ขึ้นไป | ถูกพูดถึงบ่อย |

เกณฑ์นี้เป็น heuristic เพื่อสื่อ “จำนวนแหล่งหลักฐาน” ให้ผู้ใช้เข้าใจง่าย ไม่ใช่ confidence score ทางสถิติ และไม่ได้รับรองว่าข้อความนั้นเป็นข้อเท็จจริงปัจจุบันของร้าน

## ข้อจำกัด

- รีวิวเป็นประสบการณ์ของผู้ใช้ ไม่ใช่ข้อมูลทางการ และสภาพร้านอาจเปลี่ยนตามเวลา
- คำไทยประชด คำสะกดผิด ภาษาถิ่น หรือความหมายที่ต้องอาศัยบริบทยาวอาจยังตีความผิด
- การพบหนึ่งรีวิวแสดงเป็นข้อมูลเบื้องต้นเสมอ ไม่ยกระดับเป็นข้อสรุปทั่วไป
- ระบบไม่ควรรับรองเรื่องสารก่อภูมิแพ้ ฮาลาล เวลาเปิด ราคา หรือช่องทางชำระเงินแทนร้าน จึงแนะนำให้ยืนยันกับร้านโดยตรง
- รายการ cue ทั้งหมดอยู่ใน `core/practical_rules.py` เพื่อให้ตรวจ แก้ และเพิ่มชุดทดสอบได้อย่างโปร่งใส
